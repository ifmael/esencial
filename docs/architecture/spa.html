Frontend

SPA (React)

Diez rutas, un layout que las envuelve y ni una línea de estado global. Cada pantalla pide lo que necesita al API con su propio hook y lo pinta; el navegador nunca navega de verdad entre páginas, porque el Worker le entrega el mismo index.html y el router hace el resto.

Todas menos /login se declaran dentro de un <Route element={<GuardedShell />}>, que es quien aporta el layout y el guard de sesión. /recetario/nueva se declara antes que /recetario/:id, porque si no, «nueva» se leería como un identificador.

Hueco conocido: no hay ruta comodín. No existe path="*", así que una URL que el router no reconoce no pinta nada: el Worker entrega index.html y se ve una página en blanco, no un 404. Si se quiere una pantalla de «no encontrado», hay que añadirla.

Capa de datos

Un hook por pantalla

Siete hooks (useDay, usePlanWeek, useExercises, useTemplates, useRecipes, useMealPlan, useWorkoutDay) devuelven siempre lo mismo: datos, estado de carga, error y funciones para mutar. Nada de store ni de Context.

Un cliente HTTP delgado

lib/api.ts lanza ApiError con error, field y status; sin conexión, status 0 y mensaje «No se pudo conectar con el servidor». photoSrc() convierte la clave de R2 en /api/uploads/<key>.

Los tipos se declaran a mano en el módulo que los usa —no hay cliente generado— y el contrato es el del envelope del API: el field del error es lo que permite señalar el campo culpable en el formulario.

Estilos y build

Aspecto Detalle
Tailwindv4 «CSS-first»: @import "tailwindcss" en globals.css y plugin de Vite. No existe tailwind.config.*.
Tokens--color-primary #15803d, --color-background #fafaf9, --color-surface #ffffff, --radius-card 12px, --font-sans system-ui… — los mismos valores que wireframes/DESIGN.md.
TemaSolo claro: no hay prefers-color-scheme ni variantes dark: en la app.

Buildtsc && vite build → dist/, que es el assets.directory del Worker.
Devvite con proxy de /api a http://localhost:8787 (el wrangler dev), para recarga en caliente.
