Operación

CI (GitHub Actions)

Un solo workflow, .github/workflows/ci.yml, con dos jobs que corren a la vez: el gate completo (tipos, tests y e2e) y el lint de Biome por separado. Ninguno despliega nada —el CD es de Cloudflare— y ninguno migra la base de datos.

Los gates, todos juntos

Gate Cuándo Qué ejecuta
Hook de pre-commit En cada git commit pnpm lint && pnpm typecheck (husky). No corre tests.
Job ci Push o PR a main typecheck + tests de api y web + e2e con su servidor y su base
Job lint Push o PR a main biome check . sobre todo el repo
Workers Builds Push a main Build del SPA + wrangler deploy, en el runner de Cloudflare

Con concurrency agrupado por referencia y cancel-in-progress, un push nuevo cancela la corrida anterior de la misma rama: no se encolan ejecuciones obsoletas.

La contraseña de los tests es pública a propósito. El entorno del job fija ESENCIAL_DEV_PASSWORD=hola para que predev genere el .dev.vars que la suite e2e espera, exactamente el mismo valor que inyecta el webServer de Playwright. No es un secreto de producción.
