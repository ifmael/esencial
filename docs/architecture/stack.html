E Esencial Arquitectura

Abre esta página con doble clic (file://). Sin servidor, sin build.

Fundamentos

Stack y carpetas

Un monorepo pnpm con tres paquetes y dos Workers desplegables. Lo único que llega a producción son los assets del SPA (web/dist) con el Worker del frontal, y el Worker de la API; las suites de test y esta documentación nunca viajan al runtime.

Los tres paquetes

Paquete Carpeta Qué contiene Comandos propios
@esencial/api api/ Worker de la API (Hono + D1 + R2): wrangler.toml, src/ (11 rutas, 11 módulos de soporte), migrations/, schema.sql, scripts/, tests/ test, typecheck
@esencial/web web/ SPA React 19 + Vite + react-router 7 + Tailwind 4, y el Worker del frontal: src/routes/, src/components/, src/lib/, tests/, worker/index.ts dev, build, test, typecheck
@esencial/e2e e2e/ Playwright con dos servidores y dos bases (frontal y API): tests/, playwright.config.ts, scripts/isolation-check.ts test, isolation-check, typecheck

El paquete raíz esencial no tiene código: orquesta los otros tres con pnpm --filter y pnpm -r (pnpm-workspace.yaml declara web, api y e2e).

Scripts de la raíz

Estos son los comandos que se teclean desde la raíz. Los de cada paquete se ejecutan vía pnpm --filter, que es justo lo que hacen estos.

Script Comando Para qué
dev node api/scripts/dev.ts Arranca dos servidores: dev:api en el puerto 8789 y dev:web en el 8787. Antes corre predev, que genera los dos .dev.vars.
build pnpm --filter web build Construye el SPA a web/dist, el asset dir del Worker frontal.
test pnpm --filter api test && pnpm --filter web test Vitest de API y luego de web. No incluye e2e.
e2e pnpm --filter @esencial/e2e test Playwright con dos servidores propios: frontal en 8788 y API en 8790.
typecheck pnpm -r typecheck tsc en los tres paquetes.
lint biome check . Lint + comprobación de formato de todo el repo.
db:migrate:local wrangler d1 migrations apply esencial --local -c api/wrangler.toml --persist-to .wrangler/state Migra la base local: la config vive en api/.
db:migrate:remote wrangler d1 migrations apply esencial --remote -c api/wrangler.toml Migra la base de producción (idempotente).
deploy pnpm build && wrangler deploy -c api/wrangler.toml && wrangler deploy Build del SPA (la URL de la API vive en web/.env.production), deploy de la API primero y después el frontal. Ojo: hay que invocarlo como pnpm run deploy, porque pnpm deploy es un comando interno de pnpm.

Dos trampas que cuestan una tarde. Hay dos .dev.vars con el mismo contenido —la raíz para el frontal y api/.dev.vars para la API—, ambos generados por api/scripts/ensure-dev-vars.ts: si falta uno, ese Worker no ve los secretos y el login responde 500. Y el deploy manual es pnpm run deploy, porque pnpm deploy lo captura pnpm como comando propio y falla.
