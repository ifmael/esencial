Backend

API (Hono)

38 endpoints en 11 ficheros de rutas, todos detrás de la misma cadena de middleware. La API no decide quién entra: eso lo decide la cadena, antes de que el router vea la petición. Por eso una ruta nueva no puede nacer desprotegida.

38endpoints
11ficheros de rutas
3middlewares globales
11códigos de estado
17esquemas Zod

Añadir un endpoint nuevo es añadir un fichero en api/src/routes/ y montarlo: hereda las tres fases de seguridad sin tocar ninguna. Por eso hay 3 middlewares globales para 38 endpoints y no 38 comprobaciones de sesión repetidas. Este Worker solo atiende /api/*: fuera de ahí responde 404 { error: "Not found" }, porque el SPA y su guard viven en el Worker del frontal.

Validación y errores

Todo error es JSON con la misma forma: { error, field? }. El field apunta a la pieza concreta que falló, y el SPA lo usa para pintar el error en el campo correcto.

Situación Respuesta
JSON inválido en el body400 { error: "Invalid JSON body", field: "body" }
Falla un esquema Zod400 { error: <mensaje>, field: "<ruta>" } (primer issue)
Nombre repetido (UNIQUE)400 { error: "Already exists", field: "<columna>" }
Clave foránea rota400 { error: "References a missing or in-use record", field: "reference" }
Cualquier otro fallo de D1500 { error: "Internal server error" } — sin filtrar SQL
Sin sesión en /api/*401 { error: "Unauthorized" } (lo pone el gate, no el handler)
Regla de negocio del día409 { error: "Ya hay una sesión ese día", field: "date" }

La traducción de errores de SQLite vive en un solo sitio (dbFailure en api/src/http.ts), así que ninguna ruta necesita envolver sus consultas en try/catch ni inventarse un formato de error.

Subida de fotos

El contrato

POST /api/uploads con multipart, campo file. Solo image/png, image/jpeg e image/webp, hasta 5 MB. Responde 200 { photo_path }; demasiado grande es 413, tipo fuera de la lista, 400.

Por qué no se puede mentir en la foto

Al guardar una receta, la API comprueba que photo_path case con el patrón de clave y que el objeto exista de verdad en R2 (PHOTOS.head). Si no, 400 en el campo photo_path.

Las fotos se sirven por GET /api/uploads/:key detrás del mismo gate que el resto: no hay bucket público ni URLs adivinables.
