Tres suites con tres niveles de realidad: la de API ejecuta el Worker de verdad contra una base D1 de miniflare, la de web monta componentes con fetch simulado, y la de e2e arranca sus dos servidores y sus dos bases, que nunca son las tuyas.

Las tres suites

Suite Comando Cómo corre Tamaño
API pnpm --filter api test Vitest con @cloudflare/vitest-pool-workers: el Worker real contra D1 de miniflare. fileParallelism: false porque los ficheros comparten el mismo namespace de base. 17 ficheros · 165 it() estáticos, ≈202 en ejecución
Web pnpm --filter web test Vitest con jsdom y Testing Library; tests/setup.ts stubea el fetch y responde al sondeo de /api/auth/status. 24 ficheros · 195 it() estáticos
e2e pnpm e2e Playwright contra sus dos servidores propios (frontal 8788, API 8790), con Brave si está instalado y el chromium de Playwright si no. retries: 2. 4 specs · 23 tests + 1 setup

pnpm test ejecuta API y web en ese orden. No incluye e2e: para eso está pnpm e2e, que arranca sus dos servidores con sus dos bases.

El bootstrap de la suite de API

Esquema, no migraciones

Aplica api/schema.sql + 0002 en un batch atómico y luego 0003 y 0005 partidos por punto y coma. La 0009 no se aplica: el esquema final ya la refleja y volver a ejecutarla chocaría con la reconstrucción.

Sesión de verdad

Cada instancia hace un login real con test-password-123 (el digest vive en api/tests/wrangler.test.toml) y reutiliza la cookie. Hay builders autenticados y también anonGet/anonSend para probar los 401.

La config de la suite vive en api/tests/wrangler.test.toml, no en api/wrangler.test.toml: dentro de api/, el .dev.vars de dev pisaría sus [vars] y los tests fallarían. freshDb() vacía las 18 tablas en orden hijo→padre antes de cada test, así que los tests no dependen del orden de ejecución.

Reglas al escribir e2e. Nunca hacer POST de un ejercicio del catálogo sembrado: exercises.name es UNIQUE y el API responde 400. Se resuelve con GET /api/exercises buscando por nombre. Y uso fechas reales (hoy, el lunes de esta semana), no desplazamientos por corrida.

Con la API en otro origen, los helpers pegan a ella por API_BASE / apiUrl() (e2e/tests/helpers.ts); si una petición sale del navegador, necesita credentials: "include" para llevar la cookie.
