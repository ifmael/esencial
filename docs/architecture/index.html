Visión general

Esencial, de arriba abajo

Esencial es una app de bienestar personal —recetas, plan semanal y plan de fuerza— que vive entera en un solo Worker de Cloudflare. Ese Worker sirve la API bajo /api/* y los assets del SPA en la misma URL, con una única base D1 y un bucket R2 para las fotos de recetas.

Quién contesta a cada dirección

Hay un solo programa y un solo despliegue: el mismo Worker que habla con la base de datos es el que entrega los archivos de la aplicación. Cuando abres una dirección, la petición pasa primero por las fases del diagrama y solo después se decide el destino.

Pides Quién contesta ¿Hace falta sesión?
/api/… (datos) El código de la API: 11 ficheros de rutas Sí, salvo /api/health y las de entrar y salir
/ o /plan-fuerza (una pantalla) Se entrega index.html, desde los archivos enlazados al programa Sí; sin sesión te manda a entrar
/login index.html No: es la puerta
Algo con extensión (.js, .css, .png) El archivo tal cual No: la pantalla de entrar necesita los suyos

En el dist no hay un archivo por pantalla

Lo que se publica son tres cosas y poco más. No hay una carpeta plan-fuerza ni un recetario.html: 

web/dist/
├─ index.html               ← el único documento: el esqueleto de la app
└─ assets/
   ├─ index-<código>.js     ← el programa que corre en el navegador
   └─ index-<código>.css    ← los estilos

Cuando pides una pantalla como /plan-fuerza, pasan tres cosas:

  1. El programa busca ese archivo entre los suyos y no lo encuentra.
  2. Está configurado para que, si no lo encuentra y la dirección no empieza por /api/, entregue index.html.
  3. El programa que va dentro de ese documento lee la dirección y pinta la pantalla de Plan fuerza.

Es decir: todas las pantallas devuelven el mismo documento. Por eso el control de acceso ocurre antes de la entrega y no dentro de la aplicación — dentro ya no habría nada que evitar, la descarga ya habría pasado.

Dos momentos distintos

  • Primera entrega — primera visita, recarga, enlace pegado o un dispositivo nuevo: el navegador pregunta al servidor, y ahí actúan authGuard y pageGuard.
  • Aplicación ya abierta — moverse entre pantallas no pide ningún documento: el control lo hace la propia app preguntando por /api/auth/status.

Las dos mitades no se hablan por la red

El código de la API lee la base y las fotos directamente, con los enlaces que Cloudflare le da al Worker (DB y PHOTOS), no pidiendo otra URL. Por eso no hay CORS que configurar, hay una sola dirección, y una pantalla y su endpoint se despliegan juntos: cambia el SPA, cambia en la misma publicación.

Compruébalo en 30 segundos. Ejecuta pnpm build y luego ls web/dist web/dist/assets: verás index.html, el JavaScript y el CSS. Ninguna carpeta por pantalla.

Las cinco decisiones que explican esta arquitectura

Todo lo demás en este sitio es consecuencia de estas cinco. Cada una tiene su sección.

  1. Un Worker hace de frontend y de backend. wrangler.toml fija main, un binding ASSETS hacia web/dist y run_worker_first = true: cada petición pasa por el Worker, también las páginas HTML. Un solo despliegue, una sola URL, sin CORS.
  2. Un middleware global decide el acceso. Las cabeceras de seguridad y los dos guards viven en api/src/middleware.ts, así que ninguna ruta nueva puede nacer desprotegida por descuido.
  3. D1 es la única fuente de verdad, y se versiona por migraciones numeradas. api/schema.sql es el estado final; 0001 es el baseline congelado y los cambios viven en deltas (aditivos o destructivos) con su propio número.
  4. La sesión-día es la unidad de planificación (Fuerza v2). Una plantilla es una agrupación semántica que se expande en el día y desaparece como entidad; lo duradero es el día. Se aplica con UNIQUE en base, validación en la API y bloqueo en la UI.
  5. El gate es un test que falla primero. TDD en cada cambio, y CI que ejecuta typecheck, test, e2e y lint en dos jobs de GitHub Actions antes de tocar main.

Cómo leer este sitio. Son ficheros HTML estáticos: no hay build, ni dependencias, ni peticiones de red. Los diagramas son SVG en línea, así que también se ven sin conexión, y el tema claro/oscuro lo elige tu sistema.
