# CI + Deploy automático (Fase 1 + 4A del TODO.md) — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CI en GitHub Actions (unit + e2e) y deploy automático a Cloudflare vía Workers Builds en cada push a `main`.

**Architecture:** Un workflow YAML en `.github/workflows/ci.yml` con un solo job (install → unit → migraciones locales → e2e). Un cambio mínimo en `e2e/playwright.config.ts` para que `executablePath` no dependa de Brave. Deploy sin YAML: Workers Builds conectado desde el dashboard de Cloudflare.

**Tech Stack:** GitHub Actions (ubuntu-latest), pnpm 11 + Node 24, Playwright + chromium, Cloudflare Workers Builds.

**Spec:** TODO.md Fase 1 (opción B) + Fase 4 (opción A). Datos medidos: unit ~40s, e2e ~35s local; 2.000 min/mes gratis Actions, 3.000 min/mes gratis Workers Builds. Repo privado (`ifmael/esencial`).

## Global Constraints

- Conventional commits, sin `Co-Authored-By` ni atribución de IA.
- UI y datos en español.
- El e2e usa la password de dev `hola` (`e2e/tests/setup.ts:10`, `e2e/tests/auth-dia.spec.ts:18`): CI debe arrancar `wrangler dev` con `ESENCIAL_DEV_PASSWORD=hola` para que `predev` genere `.dev.vars` con esa clave.
- `wrangler d1 migrations apply` necesita stdin no-TTY: en CI ya lo es; añadir `< /dev/null` por si acaso (AGENTS.md problema 2).
- Migraciones locales son obligatorias antes del e2e: sin ellas la D1 de CI está vacía y no hay ejercicios/recetas.
- El test e2e `auth-dia.spec.ts:38` asume D1 vacía — en CI pasa (BD desde cero); NO tocar el test.

**Interfaces:**

### Task 2: Workflow de CI

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: scripts raíz `pnpm test` (unit api+web), `pnpm e2e`, `pnpm db:migrate:local`.
- Produces: job `ci` verde en push/PR a `main`.

- [ ] **Step 1: Crear `.github/workflows/ci.yml`**

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  ci:
    runs-on: ubuntu-latest
    timeout-minutes: 20
    env:
      ESENCIAL_DEV_PASSWORD: hola
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4   # lee packageManager de package.json

      - uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - run: pnpm test

      - name: Migraciones D1 locales
        run: npx wrangler d1 migrations apply esencial --local < /dev/null

      - run: pnpm --filter @esencial/e2e exec playwright install --with-deps chromium

      - run: pnpm e2e
```

- [ ] **Step 2: Commit**

```bash
git add .github/workflows/ci.yml
git commit -m "ci: workflow con unit + e2e (Fase 1 opción B)"
```

## Riesgos y rollback

- **Workers Builds:** si el build falla en su runner, rollback = desconectar el repo en el dashboard (deploy manual sigue funcionando con `npm run deploy`).
- **Actions flaky:** el test `auth-dia.spec.ts:38` es determinista en CI (BD vacía); si otro test resulta flaky bajo carga, `retries: 2` del config lo cubre.
- **Coste:** $0 esperado (2.000 min/mes Actions ≈ 400 runs; 3.000 min/mes Workers Builds ≈ 500 builds). Sin tarjeta en GitHub no hay cargo posible: la quota agotada bloquea, no factura.
